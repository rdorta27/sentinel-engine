Reproducir

Clona el repositorio, ejecuta las pruebas y repite una corrida congelada sin conexión. No se necesita clave de modelo, credencial de nube ni datos.

git clone https://github.com/rdorta27/sentinel-engine.git
cd sentinel-engine/sentinel-ai-core
pip install -e ".[dev,eval]"
SENTINEL_WRITE_EVIDENCE=0 python3 -m pytest -q
export SENTINEL_LLM_CHEAP_MODEL=accounts/fireworks/models/glm-5p3-flash
export SENTINEL_LLM_STRONG_MODEL=accounts/fireworks/models/glm-5p3-flash
python3 -m eval.run verify 2024Q4-train-v1

Los dos nombres de modelo son públicos. No son claves. El comando verify no hace ninguna llamada real. Recalcula una corrida congelada a partir de sus grabaciones y la compara con su summary.json. Hoy 2024Q4-train-v1 coincide. Las corridas 2024Q4-resolution-v1 y 2024Q4-resolution-v2 difieren de una repetición del código actual, porque el código cambió después de medirlas. Una corrida congelada nunca se edita: una medición nueva es una corrida nueva. Índice de evidencia.

La suite de ataques escribe una corrida nueva solo cuando lo pides: SENTINEL_WRITE_EVIDENCE=1 python3 -m pytest tests/adversarial -q.

IA responsable

Lo que el modelo nunca recibe

  • El id del cliente. Las herramientas están ligadas a la sesión.
  • Identificadores personales. El código los enmascara por patrón antes de cualquier llamada al modelo.
  • La decisión. El modelo etiqueta la intención. Decide el motor de políticas.

Límite: el enmascaramiento solo encuentra los patrones que conoce. No encuentra otros datos personales. Decisión 004.

Cada decisión tiene una razón

  • El motor de políticas devuelve un id de regla con cada decisión.
  • Un «¿por qué?» posterior recibe la decisión guardada. El modelo no inventa una respuesta nueva.
  • El asesor ve la traza de cada paso.

Preguntas que hace un jurado

¿Está en producción?

No. Es un prototipo. Ejecuta el código que ejecutaría producción, con mocks documentados. Ningún número de este sitio es una medición de producción.

¿Qué es un mock?

Un sustituto con el mismo contrato que la pieza de producción. Producción reemplaza el backend y conserva el código. La página de mocks lista cada uno con su límite. El diagrama de arquitectura los marca.

¿Por qué el techo de resolución es 16 de 56?

La política deja resolver solo esos casos simulados. Los demás casos deben terminar en un traspaso o en una pregunta. Tanto la línea base como el enrutador LLM resuelven todos los casos bajo el techo. El conjunto no puede distinguirlos en resolución.

Entonces, ¿qué aporta el enrutador LLM?

Etiqueta mejor la intención: 81.8% frente a 69.2% de la línea base de palabras clave en 308 turnos reservados. Es una simulación con casos escritos por el equipo.

¿Decide el modelo?

No. El modelo etiqueta la intención. El código enmascara, busca, decide, actúa y vuelve a leer el caso.
