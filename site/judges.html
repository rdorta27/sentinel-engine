Reproduce

Clone the repository, run the tests and replay a frozen run offline. No model key, no cloud credential and no data are needed.

git clone https://github.com/rdorta27/sentinel-engine.git
cd sentinel-engine/sentinel-ai-core
pip install -e ".[dev,eval]"
SENTINEL_WRITE_EVIDENCE=0 python3 -m pytest -q
export SENTINEL_LLM_CHEAP_MODEL=accounts/fireworks/models/glm-5p3-flash
export SENTINEL_LLM_STRONG_MODEL=accounts/fireworks/models/glm-5p3-flash
python3 -m eval.run verify 2024Q4-train-v1

The two model names are public. They are not keys. The verify command makes no live call. It recomputes a frozen run from its recordings and compares it with its summary.json. Today 2024Q4-train-v1 matches. The runs 2024Q4-resolution-v1 and 2024Q4-resolution-v2 differ from a replay of the current code, because the code changed after they were measured. A frozen run is never edited: a new measurement is a new run. Evidence index.

The attack suite writes a new run only when you ask for it: SENTINEL_WRITE_EVIDENCE=1 python3 -m pytest tests/adversarial -q.

Responsible AI

What the model never receives

  • The customer id. The tools are bound to the session.
  • Personal identifiers. Code masks them by pattern before any model call.
  • The decision. The model labels the intent. The policy engine decides.

Limit: the masking finds only the patterns that it knows. It does not find other personal data. Decision 004.

Every decision has a reason

  • The policy engine returns a rule id with each decision.
  • A later "why?" gets the stored decision. The model does not make up a new answer.
  • The advisor sees the trace of each step.

Questions a judge asks

Is it in production?

No. It is a prototype. It runs the code that production would run, with documented mocks. No number on this site is a production measurement.

What is a mock?

A stand-in with the same contract as the production part. Production replaces the backend and keeps the code. The mocks page lists each one with its limit. The architecture diagram marks them.

Why is the resolution ceiling 16 of 56?

The policy lets only those simulated cases resolve. The other cases must end in a handoff or a question. Both the baseline and the LLM router resolve every case under the ceiling. The set cannot tell them apart on resolution.

Then what does the LLM router add?

It labels the intent better: 81.8% against 69.2% for the keyword baseline on 308 held-out turns. That is a simulation on team-written cases.

Does the model decide?

No. The model labels the intent. Code masks, looks up, decides, acts and reads the case back.
